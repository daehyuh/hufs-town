# Browser compatibility smoke

Run the desktop engine smoke with `pnpm test:e2e:browser-compat`. Playwright browser builds must be installed first with `pnpm exec playwright install chromium firefox webkit`.

The test uses mocked auth, guest-admission, bootstrap, and World WebSocket responses. It checks anonymous guest entry, the Phaser canvas starting, the preflight media guidance and feature detection, and the low-spec setting persisting while the world renderer restarts. The normal E2E suite remains Chromium-only; Firefox and WebKit projects run this smoke file only.

In the Windows Playwright WebKit build, `navigator.mediaDevices.getUserMedia` is unavailable even on localhost. The test expects the UI to explain that device checks are unsupported and disable the microphone/camera test controls. This is evidence of graceful handling in that Playwright build, not a statement about Safari on macOS or iOS.

The Tailscale IP preview is served over plain HTTP and is not a secure browser context. Client operation IDs use `crypto.randomUUID()` when available and fall back to Web Crypto random bytes so actions still work on that origin. Microphone, camera, and screen-capture APIs still require a secure context.

The implemented anonymous media preview path is `scripts/dev.ps1 start -Profile preview -TailnetHttpsPreview`. It configures Tailscale Serve at the device's MagicDNS HTTPS origin, uses a Secure session cookie, permits that exact origin in API/World, and proxies same-origin API and WebSocket paths to isolated preview services. A separate SFU advertises and binds its WebRTC TCP/UDP port to the PC's Tailscale IPv4. The internal media-control endpoint remains loopback-only. This is designed to enable secure-context media capture on a tailnet-connected phone without adding SSO credentials to the preview. In the 2026-09-28 local attempt the Media container became healthy and API/World health checks passed, but Tailscale Serve did not activate and the HTTPS URL did not respond; the phone path is therefore not yet verified. It does not verify HUFS SSO or an external TURN route, and Windows Firewall or tailnet ACLs can still block UDP.

The local API can advertise a loopback World URL such as `ws://localhost:18091/world/socket`. A remote browser would resolve that address on the phone itself, so the client rewrites loopback World endpoints to the current page's same-origin `/world` WebSocket proxy. Local browsers keep using the configured loopback endpoint. The Tailscale Chromium E2E supplies the loopback API response and verifies the rewritten socket URL; it mocks the World protocol and is not a live phone session test. The currently running Docker API instead advertises `ws://100.87.52.42:5173/world/socket`; an unauthenticated upgrade through Vite returned the same 403 as a direct World request, consistent with the synthetic ticket being rejected. This does not verify the signed-in phone's ticket or room join.

This smoke does not grant or use a real microphone or camera, negotiate real peer media, test screen capture, or measure frame rate and resource use on low-spec hardware. Those checks still need real desktop browsers and representative phones/tablets before T25.3 can be considered complete.
