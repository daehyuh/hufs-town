# 아바타 옷장과 프로필

HUFS SSO 프로필에 이름과 아바타 외형을 저장하고, 월드 참가자와 채팅에 같은 모습을 표시한다. 로그인하지 않은 로컬 미리보기는 이름·외형·소개·링크를 브라우저에 저장해 다시 방문해도 유지한다.

## 제공 파츠

`C:/Project/hufstown/디자인에셋/Pixel Art (6364)/RPG (1437)/Characters (1094)/Make-Your-Own Pieces (587)` 원본을 사용한다. 생성 스크립트는 서로 다른 체형에서 모두 쓸 수 있는 공통 의상·헤어만 골라 프론트의 `public/assets/avatar-parts`에 둔다. 현재 옷장에는 체형 3종, 피부색 10종, 공통 의상 65종, 공통 헤어 88종이 있다. 파츠 PNG는 원본 전체가 아니라 필요한 목록만 배포 번들에 복사하고 월드 화면에서는 실제 접속자의 조합을 지연 로드한다.

`scripts/prepare-assets.mjs`가 프론트 카탈로그와 Java `AvatarCatalog`를 같은 원본 목록에서 생성한다. 사용자는 입장 화면에서 3개 체형 프리셋, 피부색, 의상, 헤어를 고르고 실제 파츠 레이어 조합을 미리 본다. 무작위 꾸미기는 이 목록에서 한 조합을 선택한다.

원본 파일을 사용할 권리는 확인하지 않았다. 공개 배포 전 GDG HUFS 로고·일러스트와 픽셀 아트 파츠 각각의 배포 범위를 확인해야 한다. 사용자가 직접 업로드하는 파츠는 지원하지 않는다.

## 저장과 접속

- Flyway V8이 `app_user`에 피부색·의상·헤어 필드를 추가하고 기존 3개 프리셋을 기본 캐주얼 의상으로 변환한다. 채팅 이력에도 발신 당시 외형을 보존한다.
- 프로필 API는 생성 카탈로그의 허용값만 받고 이름은 20자, 제어문자 제외 규칙을 적용한다. 인증 사용자는 월드 Join 요청의 외형값을 신뢰하지 않고 저장된 SSO 프로필을 사용한다.
- 월드 안의 `내 옷장`은 이름·체형·피부색·의상·헤어·소개·외부 링크를 편집한다. 인증된 계정은 API에 저장한 뒤 `profileUpdate` WebSocket 메시지로 현재 접속 중인 PlayerView도 갱신한다. 미리보기는 같은 초안 전체를 localStorage에 저장한다.
- HTTP(S) 링크의 scheme은 대소문자를 구분하지 않는다. API와 월드 WebSocket은 길이·개수·형식을 다시 검사한다.
- Redis 세션에 이전 버전 프로필이 남아 있어 외형 필드가 비었거나 카탈로그에서 사라졌더라도 `TownPrincipal.from`에서 안전한 기본값으로 정규화한다.
- 새 필수 외형 필드 때문에 월드 Join/Welcome과 WebSocket subprotocol을 v2로 올렸다. 배포 중인 이전 v1 클라이언트는 v2 월드에 다시 연결해야 한다.
- 로비에서 SSO 프로필을 바꾸면 다음 입장부터 적용된다. 월드 안에서 옷장을 저장하면 API 저장과 `profileUpdate`를 함께 수행해 현재 참가자 이름표·외형·프로필 카드도 바로 갱신한다. 미리보기는 브라우저에 프로필을 저장하고 다시 입장할 때 서버에 프로필 상세를 재전송한다.

## 렌더링과 한계

Canvas에서 체형·피부·의상·헤어 spritesheet를 조합한다. Phaser 텍스처 캐시에 이미 있는 파츠는 재사용하고, 새 참가자가 들어올 때 필요한 세 장만 지연 로드한다. 참조 계수가 0이 된 파츠는 캐시에서 제거하며, 참가자 퇴장·로딩 도중 취소·장면 종료 때도 남은 참조와 텍스처를 정리한다. 새 이미지 로드가 끝나면 해당 아바타 레이어만 교체하며 기존 기본 아바타 시트는 로드 실패 시 대체 모습으로 남는다. 참가자 목록과 채팅 이력에서도 저장된 외형을 표시한다.

입장 대화상자와 월드 안의 `내 옷장`에서 프로필을 편집할 수 있다. 소개글과 외부 링크(최대 3개)는 V24로 저장하고 월드 프로필 카드에 표시한다. 사용자 파츠 업로드는 아직 미구현이며 이름/선택 UI의 일부 명칭은 원본 파츠의 영문 ID를 한국어 단어 조합으로 표시한다.
