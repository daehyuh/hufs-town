# 오피스와 맵 편집기

기본 공간을 48×34칸 오피스로 교체했다. 회의실 2개, 중앙 업무석, 카페 라운지, 집중 업무실, 리셉션을 연결하고 73개 오브젝트를 배치했다. 제공된 아바타·GDG 로고·실내 식물을 활용하고, 부족한 사무실 가구는 코드로 생성하는 픽셀 SVG로 보완했다. 카탈로그는 24종이다. 원본 에셋은 수정하지 않았다.

아바타 시트를 실제 렌더링해 확인한 방향 행은 아래 0 / 왼쪽 1 / 오른쪽 2 / 위 3이다. 이전의 잘못된 행 연결을 수정했다. 멈출 때 중립 프레임으로 돌아가고, 벽에 막힌 상태에서는 걷기 프레임을 반복하지 않는다. 3종 프리셋을 유지하며 임의 의상 조합은 후속 작업이다.

## 사용

`http://localhost:5173/` 로그인 → 내가 만든 공간 카드의 **맵 편집** 버튼.

- 가구 검색·분류, 배치 미리보기, 0.5칸 스냅, 드래그 이동, Shift 다중 선택, 복제·삭제, 속성 편집. 그리드 표시는 1칸 주요선과 0.5칸 보조선을 보여 주며, 격자 스냅은 표시와 별도로 켜고 끌 수 있다. 정밀 배치 모드에서는 포인터 위치를 그대로 사용한다. 배치 전 방향을 선택하거나 선택한 오브젝트의 방향을 바꾸면 스프라이트와 충돌 영역이 함께 회전한다. 방향 변경으로 맵 경계를 벗어나면 적용하지 않는다.
- 바닥·벽 직사각형 도구, 독립/공용/조용한 구역, 이벤트 발표 무대, 시작점, 안내 문구.
- 브러시(R)는 드래그 경로를 보간해 0.5칸 셀을 칠하고, 한 드래그를 한 번의 실행 취소 단계로 저장한다. 채우기(B)는 클릭한 칸의 보이는 바닥 재질을 기준으로 상하좌우 연결 영역을 찾고 벽에서 멈춘다. 두 도구 모두 결과를 직사각형 패치로 압축하고 바닥 256개 제한을 넘는 변경은 적용하지 않는다.
- 시작점은 현재 이동 충돌 규칙으로 즉시 검사한다. 이동 가능한 시작점은 초록색, 벽/가구와 겹치는 시작점과 도구 미리보기는 빨간색으로 표시하며 키보드 포커스 중 방향키와 Enter로도 시작점을 지정할 수 있다. 서버 게시 검증은 계속 최종 권한으로 적용된다.
- PRIVATE 구역은 2~100명 정원을 설정하며, 이전 지도는 12명 기본값을 사용한다. PUBLIC은 근거리 통화와 발표 참가, SILENT는 모든 미디어 송출 중지, STAGE는 지도에 지정 무대가 있을 때 발표자로 허가된 참가자도 무대 안에서만 송출하도록 적용한다. 무대는 지도 편집기·미니맵·실제 월드에 표시되고, 3×2칸 미만은 게시할 수 없다. 발표 모드가 아니면 무대는 공용 근거리 구역처럼 동작하며, PRIVATE 회의실은 발표가 진행 중이어도 독립 통화 정책을 유지한다.
- 실행 취소/다시 실행 50단계, 키보드 단축키, 충돌/구역 오버레이, 줌·화면 맞춤.
- 2.5초 주기 자동 저장, 명시적 저장·게시, 최근 20개 게시 이력과 복원.
- JSON 내보내기/가져오기와 저장 실패 시 같은 브라우저의 로컬 복구본.
- 레이어별 잠금과 같은 레이어의 앞/뒤 순서 조정. 잠긴 항목은 선택·이동·삭제·속성 편집·복제·순서 변경에서 제외하고, 오브젝트는 같은 깊이에서 저장된 배열 순서를 렌더링 순서에 반영한다.
- 안내 문구에 선택형 HTTP(S) 링크를 지정하면 월드에서 문구를 클릭해 새 탭으로 열 수 있다. 링크는 공용 맵 스키마와 Java 검증기에서 형식·길이를 다시 검사한다.
- 가구 상호작용의 이미지 게시판은 현재 공간에 업로드한 이미지 ID만 참조한다. 서버가 같은 공간의 READY 에셋을 검증하고 게시/초안이 참조 중인 이미지는 삭제를 막는다. 월드에서 가구를 클릭하면 이미지와 설명을 접근성 있는 대화상자로 표시한다.
- 새 이미지 업로드는 `PENDING` 격리 상태로 시작한다. 공간 소유자는 검수 대기 목록에서 서버가 재인코딩한 썸네일을 확인하고 승인하거나 거절할 수 있다. 승인된 `READY` 에셋만 일반 월드/에디터 목록, 콘텐츠 조회, 맵 참조에 노출되며 미승인 파일은 월드에서 읽을 수 없다. 거절 파일은 저장 파일을 제거하고 동일 파일은 다시 제출할 수 있다.
- 업로드는 PNG/JPEG MIME와 디코더가 판정한 실제 파일 형식의 일치, 2MB 이하, 2048×2048 이하 픽셀 범위를 검사한 뒤 원본을 그대로 저장하지 않고 최대 512px PNG로 다시 인코딩한다. 업로드당 썸네일은 최대 96px이며 공간별 500개/100MB 한도를 적용한다. Testcontainers에서 SVG·MIME 위장·크기/차원 초과 거부, JPEG 변환 결과와 썸네일 크기, 승인 전 콘텐츠 및 맵 참조 거부를 확인했다.
- 맵 JSON 가져오기는 공유 JSON Schema에 더해 서버와 동일한 맵 크기/스폰/사각형 경계, 모든 요소 ID, 오브젝트 좌표, 포털 목적지, 대화 구역 겹침을 검사한다. `map-validation-cases.json`의 공유 판정 사례를 Java `MapRules`와 React `importMap`이 함께 사용해 허용·거부 결과가 어긋나지 않게 회귀 검사한다.
- 공유 게시판 상호작용은 게시 맵의 가구 ID를 게시판 키로 사용한다. SSO API는 현재 게시본에서 BOARD 오브젝트인지 확인하고 공간 권한을 검사한 뒤 최근 50개 글을 반환한다. 글은 500자, 사용자당 분당 5회, 게시판당 200개로 제한하고 작성자 또는 공간 관리자만 삭제할 수 있다. 맵 게시 시 제거된 게시판의 글도 정리한다. 클라이언트는 게시판이 열려 있는 동안 10초마다 새 글을 반영한다.
- NPC 상호작용은 줄바꿈으로 최대 50개 대사를 편집하고, 월드에서 가구 스프라이트와 함께 한 줄씩 넘겨 본다. 1.25칸 밖에서 클릭하면 걸어가 접근한 뒤 대화를 열며, 경로가 없거나 이동·연결·구역 상태가 바뀌면 대기 동작을 취소한다.
- 환경음 상호작용은 HTTPS 직접 오디오 파일 URL과 1~20칸 재생 반경, 1~100 기본 볼륨을 설정한다. 월드에서는 반경 안의 가장 가까운 음원 하나를 거리 감쇠해 재생하고, 기본값은 꺼짐이다. 주변에서 버튼을 눌러 재생을 허용하며 브라우저가 자동재생을 거부하면 다시 시작할 버튼을 제공한다. 음원 호스트가 직접 오디오 파일과 브라우저 재생을 지원해야 한다.
- 포털 도구로 대상 공간 ID, 선택형 대상 지도, 도착 좌표를 지정할 수 있다. 포털 진입 시 API는 출발 공간·지도·포털 ID를 게시본과 대조하고, 목적 공간의 현재 입장 지도를 해석해 1회용 입장권에 목적 지도와 도착 위치를 넣는다. 월드는 벽/경계/PRIVATE 구역 진입을 재검사하고, 잘못된 도착 위치는 공개된 기본 시작 위치로 대체한다. 저장·게시 때 목적 공간과 지정된 지도의 존재 여부도 확인한다.
- 공간 관리자 편집기의 지도 목록에서 별도 지도를 최대 50개까지 추가하고, 기본 입장 지도를 제외한 순서를 바꿀 수 있다. 새 지도를 만들 때 현재 초안이 저장 중이면 조작을 잠그고, 저장되지 않은 변경이 있으면 먼저 저장 여부를 확인한다. 지도마다 초안·편집 lease·게시 revision·복구 이력과 Redis 캐시 키를 분리했다. 기존 지도 ID는 공간 ID를 유지해 기존 입장·포털·게시본을 보존한다.
- 가구를 선택해 공지 보드·외부 링크·영상 링크 상호작용을 지정할 수 있다. 월드에서는 공지를 대화상자로 표시하고 HTTP(S) 링크는 새 탭으로 열며, 서버가 종류·길이·URL을 다시 검사한다.
- 편집 권한은 공간 OWNER/ADMIN에게 있다. 다른 탭이 같은 지도를 편집 중이면 읽기 모드로 열고 명시적으로 권한을 가져올 수 있다. 지도별 lease이므로 한 관리자가 서로 다른 지도를 동시에 편집할 수 있다.
- 지도를 바꾸면 이전 지도 문서와 선택 상태를 즉시 비우고 새 lease를 요청한다. 로딩 중에는 기존 지도 편집을 막고, 열기에 실패하면 다시 시도할 수 있으며 비어 있는 지도에는 첫 배치 안내를 표시한다.

초안 저장은 현재 참가자에게 영향을 주지 않는다. entry map을 게시하면 새 맵이 해당 지도의 참가자에게 반영된다. 새 벽/가구와 겹친 참가자는 검증된 시작점으로 옮기고 이동 epoch를 바꾼다. 맵 갱신 이전 snapshot은 브라우저가 버린다. 각 지도는 참가자·근거리 채팅·찌르기·회의실·미디어 상태를 분리하며 공간 전체 채팅은 공개 지도 사이에서 전달한다. 지도 내부의 PRIVATE/SILENT 경계는 그대로 적용된다.

## 저장·검증

- Flyway V5: `space_map`, `map_revision`, `map_draft_operation`, `map_outbox`. V37은 기존 공간 지도를 첫 지도 ID로 보존하고 지도별 정렬·entry·revision·draft idempotency·outbox 키를 도입한다. MariaDB 통합 테스트로 기존 외래키와 revision 이력 backfill을 확인했다.
- DB 트랜잭션과 공간 행 잠금으로 lease/초안/게시 포인터를 직렬화한다. lease는 HTTP 세션 해시, 탭별 client UUID, 45초 만료, 증가하는 fence로 묶는다. 브라우저는 10초마다 갱신한다.
- 저장은 baseVersion과 operation UUID/content hash로 중복 재시도와 충돌을 처리한다.
- 서버가 등록 카탈로그와 벽에서 collision을 다시 만든다. 클라이언트의 collision 배열은 신뢰하지 않는다.
- 구조 검증은 알려진 에셋·재질, 유한 좌표, 경계, 중복 ID, 구역 겹침, 회의실 정원(2~100), 발표 무대 최소 크기(3×2), 항목 수 제한을 검사한다. HTTP 본문은 Content-Length가 없어도 512,000바이트로 제한한다.
- 게시 전에 시작점과 이동 가능 공간, 구역까지의 도달 가능성을 검사한다. 게시 실패 시 기존 게시본을 유지한다.
- 게시본은 불변 JSON+SHA-256으로 보관한다. 복원도 새 revision으로 추가한다. SQL outbox 재시도와 Redis의 단조 증가 sequence 비교로 지연된 전달이 과거 맵으로 되돌리지 못한다.
- 월드 노드는 접속자가 있는 공간·지도별 현재 적용 sequence를 1초 주기로 MariaDB에 heartbeat한다. actor가 새 맵을 적용한 뒤 다음 heartbeat에서 outbox target ACK를 기록하므로 Redis 캐시 기록만으로 적용 완료 처리하지 않는다. DB·Redis 접근을 이동 tick 안에서 하지 않는다.
- API outbox dispatcher는 Redis에 단조 캐시를 쓴 뒤 최근 10초 이내 heartbeat가 있는 노드별 target과 이미 최신 sequence인 노드의 ACK를 한 트랜잭션에서 기록하고 전달 완료 처리한다. 월드는 접속 중인 맵마다 최신 캐시를 확인해 알림 유실도 복구한다. 관리자는 revision별 publication endpoint에서 `PUBLISHING/APPLYING/APPLIED/DEGRADED`, 대상·적용·대기·오프라인 노드 수를 확인한다. 10초 넘게 응답이 없는 target은 상태 조회에서 만료 처리하고, 복귀한 기존 노드가 뒤늦게 적용하면 ACK로 회복한다.
- 편집기는 게시/복원 뒤 최대 12초 동안 revision별 적용 상태를 조회한다. 전 노드 ACK 전에 성공으로 단정하지 않고, 시간 내 확인되지 않거나 오프라인 노드가 있으면 적용 수와 후속 반영 안내를 표시한다.

맵 형식은 `schemaVersion=2`, WebSocket 프로토콜은 1이다. `mapChanged`와 snapshot의 `mapRevision`을 추가했다. 기존 개발 프론트는 새 빌드로 갱신해야 한다. 에셋·기본 맵은 `pnpm assets`로 함께 재생성한다.

## 검증 증거

2026-09-25 키보드 편집 조작: 포커스한 캔버스에서 방향키·Enter로 바닥, 벽, 비공개 구역, 포털 직사각형을 만들고 Escape로 현재 배치를 취소한다. 가구와 안내 문구를 포인트 위치에 배치하고, 지우기 도구는 키보드 커서 아래의 편집 가능한 항목을 지운다. 저장/자동 저장된 맵 데이터를 읽는 편집기 Playwright 전체 18/18에서 바닥·벽·포털·안내 문구와 삭제 결과, 기존 비공개 구역 배치를 확인했다.
