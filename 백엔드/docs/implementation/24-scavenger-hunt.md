# 캠퍼스 수집 퀘스트

운영자는 진행 중인 행사에서 현재 맵을 사용하는 캠퍼스 수집 퀘스트를 시작할 수 있다. 맵 에디터에서 `NPC` 상호작용과 `SCAVENGER_ITEM` 표식을 `PUBLIC` 또는 `STAGE` 구역에 각각 하나 이상 배치해야 한다. 한 맵에서 사용할 수 있는 NPC와 표식은 종류별 최대 100개이며, 표식의 제목은 최대 80자, 단서는 최대 280자다.

참가자는 표식 근처를 클릭해도 NPC와 먼저 대화하기 전에는 단서를 볼 수 없다. NPC와 표식 모두 1.5칸 이내에서 서버가 상호작용을 승인한다. 참가자는 표식마다 한 번씩 수집 점수를 얻고, 모든 표식을 모으면 5점 완주 보너스를 받는다. 점수판은 상위 20명을 보여 준다.

서버는 현재 맵 revision, 표식·NPC ID, 참가자 위치와 계정별 중복 수집 여부를 검사한다. 로그인 계정은 계정 ID로, 게스트는 플레이어 ID로 참가자를 식별한다. 상태는 참가자별로 만들어진 `eventEngagementState` WebSocket 메시지에 동기화되며, 이미 접속한 참가자와 같은 World 프로세스에 재접속한 계정은 현재 진행 상태를 복원한다. 새 라운드를 시작하면 이전 참가자별 진행도와 점수를 초기화한다. 이벤트가 끝나면 진행 상태를 제거한다.

표식의 단서는 서버에 게시된 원본 맵에만 남는다. 참가자에게 전달하는 `mapChanged` 맵 투영에서는 `SCAVENGER_ITEM` 본문을 비워, NPC 대화 전에 단서가 노출되지 않게 한다. 단서는 해당 참가자가 NPC 대화를 완료한 뒤 개인화된 행사 상태로 전달된다.

수집 동작은 기존 플레이어 이동이나 미디어 권한을 바꾸지 않는다. 월드 기능 협상에 `SCAVENGER_HUNT`를 포함해 이를 지원하지 않는 클라이언트에서는 새 UI와 동작을 숨긴다.

현재 진행도와 결과는 World 프로세스 메모리에만 있다. 같은 프로세스 안의 재접속은 복구되지만 World 재시작이나 장애 조치 뒤에는 진행도와 점수판이 복구되지 않으며, 종료된 라운드를 행사 결과 API에서 조회할 수 없다. 이 기능은 결과 영속화까지 포함하지 않는다.

2026-09-26 검증: `MapRulesTest`와 `WorldEventRosterTest`에서 단서 길이, 맵 단서 비공개, NPC 잠금 해제, 거리 검사, 중복 수집, 점수·완주 보너스, 계정 재접속, 운영자 종료, 새 라운드 초기화를 확인했다. 프런트 단위 테스트 66/66, TypeScript 검사, 계약 생성 검사(84개 Java record와 TypeScript), Prettier, 프런트 프로덕션 빌드, World `bootJar`가 통과했다. 전체 `:modules:domain:test :apps:world:test`도 통과했다. 실행 전 `RoomNotesStoreTest`가 자체 기본 DB에 적용하지 않는 이벤트 V53까지 실행하던 설정을 감지해, 해당 회의록 테스트의 Flyway 범위를 필요한 V52까지로 제한했다. 브라우저 E2E는 현재 개발 API가 HUFS SSO 모드로 응답해 테스트가 요구하는 미리보기 입장을 진행하지 못했다.
