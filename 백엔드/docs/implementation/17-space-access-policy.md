# 공간 도메인 제한과 게스트 입장

2026-09-24. 공간 관리자는 허용 이메일 도메인과 공개 공간의 로그인 없는 게스트 입장을 설정할 수 있다. 이 정책은 공간 탐색 UI 설정뿐 아니라 서버의 공간 조회, 입장, 초대, 행사 일정 경계에서 적용한다.

## 이메일 도메인 제한

- SSO 교환 뒤 userinfo 이메일에서 정규화한 도메인을 현재 HTTP session의 속성으로만 보관한다. 이메일과 도메인을 사용자 프로필 응답이나 영구 테이블에 기록하지 않는다.
- V43 `space_allowed_email_domain`은 공간마다 허용 도메인을 저장한다. 빈 목록은 제한 없음이다. 정책 값은 소문자로 정규화하고 잘못된 입력이나 wildcard 패턴은 거부한다.
- 허용되지 않은 비멤버 계정은 공개·링크 공개 탐색 목록, 공간 상세, 참가 요청과 입장에서 같은 일반 숨김 응답을 받는다. 기존 멤버는 이메일 도메인이 이후 변경되어도 접근 권한을 유지한다.
- 초대는 승인 대기를 건너뛸 수 있지만 공간 도메인 정책을 건너뛰지 못한다. 이미 멤버인 계정의 재시도는 멱등하게 허용한다. 예정 행사 조회와 RSVP도 공간의 공통 읽기 정책을 사용한다.
- 도메인 목록은 소유자 공간 설정 화면에서 입력하며 쉼표나 줄바꿈으로 구분한다. 게스트 입장은 비공개/링크 공개, 승인제, 도메인 제한과 함께 켤 수 없다.

## 로그인 없는 게스트

- V44 `town_space.guest_entry_enabled`는 PUBLIC 공간에서만 켤 수 있다. 승인제나 이메일 도메인 제한이 함께 있으면 서버가 설정 변경을 거부한다.
- 게스트 URL의 fragment로 들어온 공간 ID를 브라우저 세션에 보관하고, 허용 공간인지 확인한 뒤 이름과 아바타를 입력하는 입장 화면을 보여준다.
- 게스트 프로필과 현재 세션 표식은 짧은 HTTP session에만 저장한다. `app_user` 행이나 `space_member` 행을 생성하지 않으며 관리자·찌르기 권한을 주지 않는다. 기본 지도 외 지도 선택과 포털 이동도 허용하지 않는다.
- 게스트의 `HUFS_TOWN_GUEST` 쿠키는 256비트 무작위 브라우저 토큰이며, 서버는 SHA-256에서 UUID를 유도해 익명 게스트 제재 주체로 사용한다. 쿠키 원문을 DB에 기록하지 않고 `HttpOnly`, `SameSite=Lax`, 로그인 세션과 같은 Secure 설정, `/api/v1/guest` 경로, 입장 때 갱신되는 190일 Max-Age를 적용한다. 이 값은 브라우저 범위의 가명 식별자이며 사람이나 계정을 확인하지 않는다. 쿠키 삭제 또는 다른 브라우저 사용은 새 게스트 범위를 만든다.
- 입장 티켓은 유도한 guest ID, HTTP session, 공간과 지도에 묶고 30초 안에 한 번만 쓴다. 요청 IP 단위 생성은 Redis로 분당 30회 제한한다. 짧은 게스트 HTTP session은 30분 비활성 후 만료되어도 브라우저 토큰은 유지되므로 새 session에서 기존 브라우저 제재를 확인한다.
- 소유자가 게스트 입장을 끄면 새 티켓 발급을 거부한다. 이미 발급된 티켓도 짧은 만료와 1회 사용 경계 안에 머문다. 같은 브라우저에서 SSO 로그인으로 전환할 때 세션의 guest marker를 제거한다.

## 검증

Testcontainers MariaDB/Redis 검사에서 도메인 제한 검색·상세·참가 요청·직접 입장, 기존 멤버 도메인 변경, 초대 거부/수락/멱등 재시도, 도메인 제한 행사 조회를 확인했다. 별도 guest 검사는 PUBLIC 외 공간·승인제·도메인 제한 거부, 세션 연결 입장, 다른 세션/재사용 입장권 거부, guest WebSocket handshake, 비계정·비관리자 동작, SSO 계정 승격을 확인했다.

관리자 공간 설정 Playwright 4/4, 게스트 링크의 비로그인 프로필/아바타 화면과 권한 거부 안내 Playwright 2/2, 프론트 production build가 통과했다. UI 검사는 인증·공간 API를 대역으로 사용하고, 실제 권한과 WebSocket handshake는 Testcontainers 통합 검사가 맡는다. 공간 복제와 보관은 각각 [복제 기록](19-space-cloning.md), [보관 기록](18-space-archiving.md)을 따른다. 실제 HUFS IdP 복수 계정 권한 검수와 영구 삭제는 T07에 남아 있다.
