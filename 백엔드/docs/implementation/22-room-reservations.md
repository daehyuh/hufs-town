# 회의실 예약

공간에 게시된 지도 안의 `PRIVATE` 구역을 회의실로 예약한다. 예약은 공간·지도·구역·주최자에 연결하며, 날짜는 UTC `Instant`로 저장하고 브라우저는 사용자의 현지 시간대로 표시한다. V52 `town_room_reservation`은 예약, 멱등 요청 키, 수정 시각, 취소 상태를 보관한다.

## 권한과 규칙

- 읽을 수 있는 공간의 예약 목록과 현재 예약 가능한 게시 회의실은 로그인 사용자에게 보여준다. 예약 생성은 공간 멤버만 할 수 있다. 본인 예약과 OWNER/ADMIN 예약만 수정·취소할 수 있다.
- 예약은 현재 게시된 지도에 있는 `PRIVATE` 구역이어야 한다. 지도가 삭제되거나 해당 구역이 더 이상 게시되지 않으면 기존 내역은 보존하되 이용 불가로 표시하고, 그 예약으로 입장하지 못하게 한다.
- 시작 시각은 현재로부터 2분~365일, 길이는 15분~8시간이다. 시간 구간은 시작 포함·종료 제외로 비교한다. 시작 15분 전부터 종료 시각까지 예약 지도에 입장할 수 있다.
- 한 사용자는 종료 전인 예약을 최대 5개까지 만들 수 있고 API는 사용자별 분당 60회로 제한한다. create 요청 ID와 payload 해시로 재시도를 멱등 처리한다. 수정은 `expectedUpdatedAt` 비교로 오래된 화면의 덮어쓰기를 막는다.
- 겹치는 생성·수정·취소 요청은 API 노드 공통 Redis 잠금과 MariaDB 트랜잭션으로 직렬화한다. 잠금을 기다리는 최대 시간은 10초이며 잠금 키는 2분 후 만료한다. 취소는 이후 시간의 다른 예약을 가능하게 한다.
- 초대/멤버 권한은 공간의 기존 입장·차단 정책을 따른다. 접근 차단 계정은 공간과 예약을 볼 수 없다. 계정 탈퇴 시 예약은 취소하고 주최자 참조를 제거하며, 멤버 강퇴 때 해당 멤버의 미래 예약을 취소한다.

## API와 화면

`GET/POST /api/v1/spaces/{spaceId}/room-reservations`로 목록/생성을 제공하고, `PATCH`와 `DELETE /{reservationId}`로 수정/취소한다. 기존 admission 요청은 선택적 `reservationId`를 받아 예약 시간·공간 접근·게시 회의실을 확인한 뒤 해당 지도 입장권을 발급한다. 예약 입장 요청은 포털 목적지 증명과 함께 사용할 수 없다.

Space Lobby에서 각 공간의 예약 창을 열 수 있다. 창은 회의실 선택, 시작·종료 현지 시각, 예약/수정/취소, 주최자·예약 상태, 현재 사용할 수 없는 지도 안내와 예약 지도 입장을 제공한다. OWNER/ADMIN만 예약 가능한 회의실이 없을 때 지도 편집기로 이동하는 버튼을 볼 수 있다.

## 검증 범위

MariaDB 11.4와 Redis Testcontainers에서 예약 목록과 멤버 권한, create 재시도, 주최자 외 수정 거부, 예약 시간 안팎 admission, 운영자 수정·취소, 동시 겹침 예약의 단일 승리, 취소 뒤 시간대 재사용을 확인한다. 프론트에서는 예약 폼·멱등 요청·권한에 따른 편집 동작·타입 검사·단위 테스트·프로덕션 빌드를 검증한다. OpenAPI 계약은 `contracts/openapi.yaml`과 동기화한다.
