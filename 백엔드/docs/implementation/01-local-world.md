# 첫 구현 — 로컬 캠퍼스와 실시간 월드

현재 범위는 G0의 첫 동작 구간이다. 전체 서비스나 R0/R1 출시 완료를 의미하지 않는다.

## 구현

- 프론트: React·Vite·TypeScript 앱, GDG HUFS 캠퍼스 입장 화면, 3가지 체형별 파츠 조합, Phaser 월드, 참가자 목록/검색, 안내, 구역 표시, 줌, 감정표현, 퇴장.
- 서버: Gradle API/world 분리, 공용 protocol/domain/persistence 모듈, Java/TypeScript 생성 계약, 실제 raw WebSocket 연결, 맵별 상태 쓰기 단일화, 20Hz 이동/충돌/달리기, 10Hz 전체 snapshot, 입력 seq/epoch, 300ms 입력 만료, 15초 재접속 유예.
- 송신: tick과 분리한 한정된 실행기, 세션별 직렬 송신, 제어 큐 상한 32개와 최신 전체 snapshot 1개, 지연 연결 회수. 여러 snapshot을 쌓는 대신 최신 것으로 교체한다.
- 재접속: 새 epoch의 첫 전체 snapshot을 적용한 뒤 ACK를 받지 못해 `pending`인 내 채팅만 기존 `clientMessageId`로 재전송한다. 서버 저장소의 멱등 키가 이전 연결에서 저장됐던 메시지의 중복 삽입을 막는다.
- 영속 기반: MariaDB/Redis compose, Flyway 계정/provider identity 최초 스키마, 실제 컨테이너를 사용하는 통합 검사. 후속 SSO 구현에서 로그인·프로필 영속 저장을 연결했다. [SSO 구현 기록](02-sso-login.md) 참조.
- 개발 도구: 고정 버전, Gradle Wrapper 배포 checksum, 로컬 start/status/stop, CI 정의, 원본 에셋 카탈로그와 선택 복사 스크립트.

## 아직 남은 범위

1. 움직임 변경분/AOI, ACK 기반 입력 재실행, 느린 네트워크에서 송신 시간 상한·자원 회수 검사. 현재 예측은 보정 방식이고 전체 snapshot을 사용한다.
2. MediaPolicy/SFU 권한과 TURN의 배포 환경 검증, GDG HUFS SSO 실 계정 검증. 마이크·카메라·화면 공유 경로와 모바일 미지원 안내는 구현했다. 실제 제품 모듈 100개를 띄운 격리 검사에서 발표자 1명→청취자 99명의 ICE/DTLS 및 RTP를 확인했지만, 실기기·TURN·SSO/좌석 예약 결합·양방향 12인 통화 검증은 남아 있다. SSO 코드·세션·프로필·월드 인증은 구현했고 IdP 운영 계정 검증은 남아 있다.
3. 정식 공간·초대·권한·Redis 100명 예약, 맵 편집, 나머지 태스크.

preview 월드와 Docker World 각각 한 프로세스에서 100명 WebSocket 이동과 정원 거부를 확인했다. Docker 경로는 Compose의 MariaDB/Redis와 함께 실행했지만 부하 클라이언트는 인증·좌석 예약을 우회하는 preview 모드였다. 실제 제품 `WorldConnection`·`MediaController` 100개 모듈을 격리 실행해 월드 이동·공간 채팅·발표자 1명에서 청취자 99명으로의 WebRTC RTP fan-out도 확인했다. 장시간 Docker 부하, SSO 입장·DB/Redis 좌석 예약 결합 부하, 다중 World 노드, 전체 React UI 100개 인스턴스와 60분 통합 부하는 아직 검증하지 않았다. 개발용 E2E와 Docker 부하 포트는 격리된 loopback 주소를 사용한다.

이동 부하 검사는 백엔드에서 `scripts/world-load.ps1 -ClientCount 25|50|100 -WarmupSeconds <초> -SteadyStateSeconds <초>`로 재실행한다. 패키징된 preview World와 별도 JVM의 클라이언트가 실제 이동 입력과 snapshot ACK를 주고받고 서버/부하 JVM의 CPU·메모리와 서버 heap·큐·연결 수를 10초 간격으로 기록한다. 컨테이너 경로는 `scripts/docker-world-load.ps1 -ClientCount 25|50|100 -WarmupSeconds <초> -SteadyStateSeconds <초>`를 사용하며, 진단용 JVM 표본은 `-RecordJfr`를 추가한다. 25/50/100명 단계 측정의 15초 평균 tick은 1.91/3.95/10.56ms, rolling p95는 2.88/7.59/20.96ms였다. 추가 100명 장시간 시험은 15분 준비와 30분 안정 측정으로 수행했다. 전원 이동, 전체 공간 명단, 338ms 수렴, 101번째 `FULL`을 확인했고 안정 구간 36,001 ticks 평균 7.87ms·마지막 rolling p95 19.91ms·표본 최대 20.96ms·50ms 초과 0회였다. 서버 CPU 54.8%·peak working set 357.8MiB, 클라이언트 JVM CPU 53.6%·peak working set 300.6MiB, 종료 큐 100/512·서버 heap 124.1MiB였다. 다만 입장/초과 구간 9 ticks 중 2회가 50ms를 넘어 합류 burst 기준을 통과하지 못했다. JFR에서 Jackson snapshot 인코딩과 WebSocket 버퍼 작성이 주요 CPU 표본으로 확인되어 내용이 같은 불변 player delta 배열의 JSON 인코딩을 재사용하도록 바꿨다. `WorldSnapshotEncoderTest` 2개와 전체 월드 테스트를 통과했고, Docker 100명 부하를 60초 예열+60초 안정 측정으로 두 번 재현했다. 두 실행 모두 전원 이동·101번째 `FULL`, 평균 tick 3.63/3.64ms, rolling p95 표본 최대 9.42/15.19ms, 50ms 초과 0회로 안정 구간 기준을 통과했다. 변경 전 같은 설정은 평균 10.29ms·p95 최대 29.34ms였다. 입장 단계는 9 ticks 중 2회, 12 ticks 중 4회가 50ms를 초과해 추가 최적화가 남는다. 두 시험의 rolling p95는 3×10초 histogram gauge이며 전체 직접 p95가 아니다. 장시간 Docker, 인증·좌석 예약 결합 부하, 실제 SFU RTP와 60분 통합 검증이 남는다. 상세 자료: [장시간 결과](evidence/26-world-load-2026-09-25-100-long-movement.json), [10초 표본](evidence/26-world-load-2026-09-25-100-long-movement.samples.jsonl), [Docker 변경 후 결과](evidence/26-world-load-2026-09-25-docker-100.json), [Docker 자원 표본](evidence/26-world-load-2026-09-25-docker-100-container-stats.txt), [변경 전 결과](evidence/26-world-load-2026-09-25-docker-100-before-array-dedup.json).

최초 실행의 Docker 미기동 문제는 사용자가 Docker를 시작한 뒤 해결했다. T01의 실제 DB 검증을 완료했으며 기본 실행을 `local`로 전환했다. T02/T03의 남은 검증은 체크리스트에 유지한다.

2026-09-26 World 충돌 검사 최적화: `Movement.canStand`가 충돌 사각형의 가장 가까운 점과 참가자 사이의 x/y 거리가 이미 충돌 반경 이상이면 `Math.hypot`을 생략한다. 반경 안에 들어올 수 있는 후보에는 기존 거리 계산을 그대로 적용해 충돌 경계 동작을 유지했다. `:modules:domain:test`와 `:apps:world:test`가 통과했다. 격리 Docker 100명 측정에서 입장 수렴 813ms, join tick 16회 중 1회 50ms 초과, 개별 join 최대 37.7ms, steady tick 평균 2.66ms·rolling p95 4.96ms·50ms 초과 0회였다. 직전 측정(771ms, 14회 중 4회 초과, p95 5.23ms)보다 입장 지표는 나아졌지만 CPU peak가 두 배 이상 달라 환경 편차가 있어 안정적인 성능 향상으로 단정하지 않는다. 2026-09-27 맵 충돌 타일 인덱스: World actor가 게시 맵을 적용할 때 충돌 사각형을 1타일 셀에 사전 색인하고, 이동 tick에서는 현재 좌표 셀의 후보만 확인하도록 바꿨다. 위치는 연속 좌표로 유지해 부드러운 이동과 원형 충돌 반경을 그대로 사용한다. 한 맵의 색인 참조 예상량이 200,000개를 넘으면 인덱스 메모리를 제한하고 원래 선형 검사로 대체한다. 게시 맵별 인덱스는 해당 맵 참가자가 없을 때 함께 정리한다. 분수 좌표 경계·경사 장애물에서 연속 검사와 결과 일치, indexed step과 기존 step 동일성, 고밀도 맵 fallback을 `MovementTest`로 검증했고 `:modules:domain:test :apps:world:test`가 통과했다. 10초 준비+30초 Docker 100명 WebSocket 이동 검사에서 100명 이동·101번째 `FULL`, 연결 484ms·명단 수렴 800ms를 확인했다. join 구간 15틱 중 2회가 50ms를 넘었으며 안정 구간 601 ticks 평균 0.695ms·3×10초 rolling p95 1.303ms·50ms 초과 0회, 종료 큐 0/0, World CPU peak 295.8%·working set 401MiB를 기록했다. 인증·좌석 예약과 실제 RTP는 포함하지 않는다([결과](evidence/26-world-load-2026-09-27-100-collision-grid-10s-30s.json), [자원 표본](evidence/26-world-load-2026-09-27-100-collision-grid-docker-stats.txt)).
