# 공동 화이트보드

맵 에디터에서 BOARD 상호작용을 지정한 오브젝트를 열면 기존 게시글과 공동 화이트보드 화면을 고를 수 있다. 화이트보드 그림은 오브젝트 ID와 공간에 연결되어, 같은 ID를 참조하는 게시 지도 사이에서 이어진다. 해당 공간의 멤버만 읽고 그릴 수 있으며, 공개 공간의 비멤버는 접근할 수 없다. 전체 지우기는 OWNER/ADMIN만 할 수 있다.

## 저장과 동시 편집

- 그림은 색상, 굵기, 최대 120개의 정규화 좌표로 이루어진 stroke다. 좌표는 0~1,000 범위이고 보드 하나에 최대 300개를 보관한다.
- API는 모든 쓰기를 문서 행 잠금 안에서 순서대로 반영한다. 서로 다른 참가자가 동시에 그려도 최신 문서에 각 stroke가 합쳐지고, 고유 operation ID로 같은 요청의 재시도가 중복 반영되지 않는다.
- 전체 지우기는 관리 권한과 확인한 문서 revision이 모두 맞아야 한다. 다른 참가자의 수정 뒤 오래된 지우기 요청은 409로 거절된다.
- 클라이언트는 1.5초마다 새 revision을 확인하고 탭이 다시 보일 때 즉시 동기화한다. 저장은 MariaDB 문서로 유지되어 다른 세션에서 다시 열어도 복구된다.
- 재시도 구분을 위한 작업 ID와 본문 해시는 180일 보관한다. 게시된 지도 어디에도 오브젝트가 남지 않으면 문서와 작업 ID를 함께 정리한다.

## 검증

Testcontainers MariaDB/Redis 통합 검사는 실제 DB 마이그레이션, 비공개 공간 접근, 두 계정의 동시 stroke 추가, 중복 요청, 새 SSO 세션에서의 복구, 관리자 전용 전체 지우기, 오래된 revision 거부를 확인한다. Chromium E2E는 도트 맵의 BOARD 오브젝트에서 화이트보드를 열고 그린 뒤 다른 참가자가 만든 변경을 폴링 동기화한다. API 통합 검사는 게시되지 않은 보드 ID와 로그인하지 않은 요청을 거절한다.

2026-09-25 구현 검증: V50 MariaDB/Redis Testcontainers 검사 통과. 공개 공간 상세를 볼 수 있지만 가입하지 않은 계정의 화이트보드 API 접근은 404로 막고, 비공개 공간의 비멤버도 차단하는 것을 확인했다. 해당 Chromium E2E와 온보딩 회귀 4/4, 프론트 Vitest 51/51, 타입 검사·프로덕션 빌드·Prettier·OpenAPI YAML 파싱·74개 계약 검사가 통과했다. 새 API 이미지의 로컬 Docker 배포 후 Flyway V50, API health `UP`, 비로그인 화이트보드 API 401, Tailnet 웹 200을 확인했다.

화면은 저해상도 벡터 stroke를 저장한다. 오프라인 상태의 편집 병합, 개별 stroke 되돌리기, 누가 그렸는지 표시하는 기능은 포함하지 않는다. T27.2 회의실 메모는 별도 권한·보존 경계를 가진다.
