# 가까운 사용자 찌르기

T16.2의 첫 소셜 상호작용으로 참가자 패널에서 가까운 사용자를 찌를 수 있게 했다. 클라이언트의 비활성화 상태는 편의 표시일 뿐이며, 최종 권한 검사는 월드 actor가 매 요청마다 수행한다.

## 요청과 권한

- 발신자와 대상은 같은 접속 공간에 연결되어 있어야 하고, 자기 자신을 대상으로 할 수 없다.
- 두 아바타 사이의 거리가 3타일 이내여야 한다. 둘 중 한 명이라도 `PRIVATE` 구역에 있으면 정확히 같은 구역에 있어야 한다.
- 받는 사람은 참가자 패널에서 찌르기를 거부할 수 있다. SSO 계정은 V33 `app_user.allow_pokes`에 설정을 저장하며 새 계정 기본값은 허용이다. `PATCH /api/v1/auth/preferences`는 CSRF 검증 뒤 설정을 저장하고 최신 계정 정보를 세션에도 반영한다. 익명 preview는 계정이 없으므로 브라우저 `localStorage`를 사용한다.
- 인증된 월드 접속은 입장 시 저장된 값을 기본값으로 적용한다. 접속 중인 각 월드 노드는 차단 목록 조회와 함께 활성 사용자의 저장 설정을 5초 간격으로 새로 읽는다. 값이 바뀌면 해당 계정의 각 연결에만 `pokePreferenceState`를 보내 설정 UI와 서버 검사를 갱신한다. DB 조회가 실패하면 기존 fail-closed 차단 데이터 준비 상태 때문에 찌르기를 허용하지 않는다.
- 발신 시도는 사용자별 3초, 수신 대상은 800ms 간격으로 제한한다. 성공 여부와 거부 사유는 발신자에게만 ACK로 전달하고, 성공 이벤트는 대상 연결에만 전송한다.
- 거리·개인 설정·쿨다운 검사를 통과한 경우에만 서버가 PokeEvent를 만든다. 브라우저가 보낸 좌표나 수신자를 fan-out에 사용하지 않는다.
- 참가자 목록의 신고는 player ID만 월드 소켓에 보내고, 월드 actor가 현재 같은 공간에 연결된 상대와 계정 ID를 직접 대조한다. API/브라우저가 임의 계정 ID를 제출할 수 없다. 계정별 하루 10건 제한, 대상 계정별 하루 1건 제한, 3초 요청 간격을 검사한 뒤 V34 `user_report`에 공간과 참가자 정보를 저장한다.

## 화면 반응

월드에 포커스를 둔 채 Z를 누르면 바라보는 방향의 가까운 사람 중 같은 구역·3타일 이내에 있는 가장 가까운 대상을 고른다. 보낼 수 있으면 발신자 앞에서 대상까지 손가락 `👉` 이모지가 240ms 동안 날아간다. 서버에서 성공 이벤트를 받은 대상은 발신자 이름이 포함된 2.6초 알림과 `👉` 표시를 보고, 픽셀 아바타가 520ms 흔들린다. 발신 이모지 이동과 수신 흔들림은 운영체제의 `prefers-reduced-motion` 설정이 켜졌으면 생략한다. 최종 거리·차단·수신 거부·쿨다운 검사는 계속 월드 서버가 수행한다. 인사·하트·박수·반짝임·웃음·응원·슬픔·축하·생각·환호·놀람·불꽃은 3초 오버레이이며 월드 서버가 허용 목록과 1.5초 쿨다운을 검사한다. 앉기는 서버 스냅샷에 유지되는 자세 토글이다. 앉아 있는 동안 픽셀 스툴과 낮아진 아바타를 표시하고, 이동 입력을 받으면 자동으로 일어난다. 앉은 상태도 재접속 뒤 PlayerView에서 복원된다. 참가자 패널의 각 행은 자기 자신, 3타일 밖, 다른 PRIVATE 구역의 사용자를 비활성화한다. 프론트 상태가 오래되거나 조작돼도 서버 검사는 그대로 적용된다.

참가자 신고는 분류와 선택 설명을 받아 기존 운영자 신고함에 저장하며, 신고자가 확인할 수 있는 것은 접수 결과뿐이다. 운영자는 신고 시 대상 계정과 공간을 확인하고 기존 검토·채팅 제한·미디어 제한·내보내기 조치를 사용할 수 있다. 메시지 신고는 메시지 원문을 증거로 보관하지만 참가자 신고는 신고 당시 이름과 공간 ID를 기록한다.

## 코드 위치와 미완료 범위

- 계약: `contracts/world.schema.json`, `scripts/generate-contracts.mjs`
- 검증·전달·속도 제한: `apps/world/src/main/java/town/hufs/world/WorldHandler.java`, `apps/world/src/main/java/town/hufs/world/UserReportStore.java`
- 신고 출처·공간·중복 방지: `modules/persistence/src/main/resources/db/migration/V34__participant_reports.sql`
- 클라이언트 설정·요청·이벤트: 프론트 workspace의 `src/game/WorldConnection.ts`
- 아바타 흔들림·감정표현 오버레이: 프론트 workspace의 `src/game/CampusScene.ts`
- 참가자 목록과 수신 거부: 프론트 workspace의 `src/app/App.tsx`, `src/app/styles.css`

실제 HUFS SSO 계정 두 개로 참가자 신고를 제출하고 운영자 신고함에서 검토하는 왕복 확인은 T24.2 운영 검수에 남아 있다. 이 신고 검수는 감정표현과 찌르기 기능 완료 기준(T16.2)과 분리한다. AWAY/DND 상태는 서버에서 찌르기를 거부하며 자세한 정책은 [접속 상태 구현 기록](09-presence-status.md)에 정리했다. 영속 계정 차단은 [별도 구현 기록](08-account-blocking.md)에 추가했다.

계정 동기화 확인(2026-09-23): `TownPrincipal`과 `/auth/me` 응답에 `allowPokes`를 포함하고, 새 월드 입장은 DB 설정을 읽는다. V33 적용 뒤 모든 활성 월드 접속도 차단 저장소의 비동기 5초 새로고침으로 동기화하고, 계정 내 설정 변경 알림을 본인 연결에만 보낸다. API/world bootJar, React production build, 64개 월드 계약 검사 통과. Docker MariaDB에서 Flyway 버전 33 성공 및 `app_user.allow_pokes` 컬럼 1개를 확인했고, 격리 SSO API health UP 및 인증 없는 설정 변경 거부(403)를 확인했다. 실제 로그인 계정으로 두 기기에서 값을 변경하는 화면 왕복은 아직 하지 않았다.

설정 영속성 통합 검증(2026-09-24): Testcontainers MariaDB/Redis를 사용하는 SSO API 통합 검사에서 기본 허용, CSRF가 포함된 `PATCH /auth/preferences`의 DB 저장, `/auth/me` 반영, 같은 SSO 주체의 새 로그인 세션에서 복원, 별도 계정 기본값 격리를 확인했다. 외부 HUFS IdP 응답은 테스트 대역이므로 실제 두 기기에서 설정 변경이 실시간 전파되는 사용성 검수는 T06.2에 남아 있다.

접근성 보강(2026-09-23): 운영체제에서 동작 줄이기를 요청했으면 찌르기 수신 시 아바타 흔들림을 생략하고 정적 표시와 알림만 제공한다. 일반 동작 설정에서는 기존 짧은 흔들림을 유지한다.

방향키 찌르기와 손가락 발사(2026-09-28): Z 키로 바라보는 방향의 같은 구역·3타일 이내 대상 중 가장 가까운 사람을 선택하고, 발신자에서 대상까지 회전된 `👉` 이모지를 날린다. 수신 측은 기존 서버 권한 검사를 통과한 경우에만 맞은 표시와 520ms 흔들림을 본다. reduced-motion 설정에서는 이동·흔들림을 생략한다. 방향별 앞쪽 대상 선택 단위 검사 3개와 두 브라우저 월드 왕복 E2E를 추가했다. 프론트 Vitest 45개 파일·151개 테스트, TypeScript·production build, Prettier, 계약 동기화 검사를 통과했다. Playwright가 E2E 12개를 발견했지만 실제 월드 E2E는 로컬 API/World가 실행되지 않아 이번에는 수행하지 못했다. 기존 Phaser 대형 청크 경고가 남아 있다.
