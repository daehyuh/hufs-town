# 공간 복제

공간 소유자는 자신의 활성 공간을 새 이름으로 복제할 수 있다. 새 공간은 항상 비공개이며, 요청한 소유자만 OWNER 멤버로 시작한다. 계정당 소유 공간 20개 제한에 보관 공간도 포함하고, 보관 중인 공간과 소유자가 없는 시스템 공간은 복제할 수 없다.

`POST /api/v1/spaces/{id}/clone`은 `{ "name": "새 공간 이름" }`을 받아 복제된 공간 정보를 반환한다. 원본의 설명, 정원, 템플릿, 허용 이메일 도메인은 유지하지만 공개 범위는 PRIVATE, 가입 승인과 게스트 입장은 꺼진 상태로 만든다. 초대·멤버·접근 차단·가입 요청·소유권 이전·즐겨찾기·채팅·게시판·행사·예약 일정은 복사하지 않는다.

복제는 모든 지도의 순서와 입장 지도를 유지하고, 각 지도의 현재 초안과 현재 게시본을 새 지도 ID 및 새 revision ID로 기록한다. 과거 revision 이력과 편집 lease·저장 작업 키는 복사하지 않는다. 새 게시 이력은 지도마다 `CLONE` revision 하나와 미전달 outbox 행으로 시작하며, Redis 캐시는 커밋 뒤 채운다. 커밋 뒤 캐시 채우기에 실패해도 outbox가 재시도하므로 복제 요청 자체는 성공을 유지한다.

승인 상태가 `READY`인 에셋 라이브러리 전체를 새 에셋 ID와 저장 키로 물리 복사한다. 대기·거절 에셋은 복사하지 않는다. 초안과 게시 문서 안의 `MapObject.asset`, `MapInteraction.assetId` 참조를 새 에셋 ID로 바꾸고, 내부 포털은 복제 공간과 해당 복제 지도 ID를 가리키도록 갱신한다. 외부 공간으로 향하는 포털은 그대로 둔다. 원본 공간 행 잠금은 지도·에셋 변경과 복제 시점을 직렬화하고, 계정 행 잠금은 동시 생성으로 공간 한도를 넘는 일을 막는다. 파일 저장이나 DB 작업이 실패하면 트랜잭션을 되돌리고 복사된 파일을 정리한다.

## 검증

`SsoIntegrationTest.wholeSpaceCloneCopiesMapsAndSettingsButStartsWithoutSocialOrPermissionRecords`는 비소유자 거부, 잘못된 이름, 여러 지도와 입장 지도, 비공개 기본값, 도메인 정책, 내부 포털 재연결, 승인 에셋의 물리 복사와 두 JSON 참조 변경, 현재 게시본과 draft 조회, 초대·멤버·차단·가입 요청·행사·일정 미복사를 Testcontainers MariaDB/Redis와 실제 API/World 프로세스로 확인한다. 실제 HUFS SSO 두 계정으로 화면에서 소유자 권한과 실시간 내보내기를 확인하는 검수는 T07.2의 남은 항목이다.
