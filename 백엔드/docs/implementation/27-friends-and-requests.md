# 친구 요청과 목록

HUFS SSO 로그인 계정은 같은 실시간 공간에서 다른 계정의 프로필을 열어 친구 요청을 보낼 수 있다. 받은 요청은 친구 창에서 수락하거나 거절하고, 보낸 요청을 취소하거나 기존 친구를 목록에서 삭제할 수 있다. 공간 사람 패널에는 받은 요청 수를 표시하며, 목록과 요청함은 15초 간격으로 갱신한다.

`user_friendship`은 UUID 순서로 정규화한 계정 쌍마다 한 행을 저장한다. 두 계정 행을 같은 순서로 잠근 뒤 관계를 생성해 동시 요청의 중복 행을 방지한다. 같은 대기 요청을 다시 보내면 기존 상태를 돌려주고, 양쪽의 요청이 교차하면 상호 의사 표시로 수락한다. 취소·거절 후 다시 요청하면 새 UUID를 발급해 오래된 요청 ID가 새 관계를 바꾸지 못하게 한다. 거절 후 24시간 대기는 데이터베이스 시각으로 판정한다. 계정별 `allow_friend_requests` 설정은 새 요청을 차단하며 기본값은 허용이다. 한 계정은 대기 중 요청을 50개까지 보낼 수 있고, 새 요청 생성은 Redis sliding window로 최근 60초 동안 20회까지 허용한다.

친구 목록과 요청 응답은 비활성/탈퇴 계정과 양방향 차단 쌍을 숨긴다. 차단을 만들면 기존 친구 및 양방향 대기 요청을 함께 지우며, 차단 해제 뒤에도 관계를 복구하지 않는다. 탈퇴 시 관계와 요청 설정을 삭제한다. 계정 검색은 표시 이름의 접두어만 대상으로 하며, 앞뒤 공백 제거와 NFC 정규화를 적용하고 검색어는 2–32 Unicode code point로 제한한다. `%`와 `_`는 SQL 와일드카드가 아니라 문자 그대로 검색한다. 결과는 활성 계정 최대 20개이며, 친구·받은/보낸 요청·24시간 재요청 대기·요청 가능·요청 거부 상태를 표시한다. 본인, 탈퇴/비활성 계정, 양방향 차단 상대는 결과에서 빠진다. 검색 응답은 계정 ID·표시 이름·관계 상태만 포함하고 이메일·접속 여부·공간·맵·좌표를 반환하지 않는다. 검색은 Redis sliding window로 계정별 최근 60초 60회까지 허용한다.

친구 설정에서 온라인 공개는 기본 꺼짐이다. 켜면 수락된 친구에게만 계정이 접속 중인지 Boolean으로 보여 준다. 위치, 공간, 맵, 세부 상태는 노출하지 않는다. World 노드는 활성 로그인 세션의 계정/플레이어 ID를 DB의 명시적 공개 설정과 대조해 Redis sorted set에 10초 lease로 발행하고 2초마다 갱신한다. API는 친구 관계·차단·DB 공개 설정을 먼저 확인한 뒤 Redis lease가 유효할 때만 `online: true`를 반환하므로 설정을 끄는 즉시 응답에서 숨겨진다. World/Redis 갱신이 끊기면 lease가 만료되어 표시도 사라진다.

친구 요청과 수락 알림은 관계 변경 트랜잭션에서 `social_push_outbox`에 기록한다. 같은 대기 요청 반복은 새 알림을 만들지 않으며, 취소/거절 후 새 관계 ID로 다시 요청하면 새 알림을 만든다. 발송 직전 관계가 여전히 유효한지, 양쪽 계정/차단 상태, 최신 알림 설정을 재검사한다. 기존 DND Redis 표식도 공유 발송 경로에서 확인하므로 DM과 친구 푸시 모두 방해 금지 중에는 보내지 않는다. 미전달은 backoff로 재시도하고 구독이 만료된 provider 응답은 구독을 제거한다. 서비스 워커는 앱이 보이는 경우 요청함/친구 목록을 갱신하고, 백그라운드 알림을 누르면 친구 창을 연다. 알림 본문에는 메시지나 위치가 포함되지 않는다.

API 계약은 `contracts/openapi.yaml`의 `/api/v1/me/friends` 경로에 있다. 검색은 `GET /api/v1/me/friends/search?q=...`에서 배열 응답으로 제공한다. 친구 설정은 요청 수신·푸시 허용·온라인 공개 세 값을 저장하며, 구버전 클라이언트가 새 Boolean을 생략하면 기존 설정을 유지한다. 정책·잘못된 입력·대상 없음·충돌·제한 초과 응답은 `{code, message}` JSON 형식으로 반환하며, OpenAPI에 주요 400/404/409/429/503 응답을 적었다. 변경된 API·World 이미지를 실행 환경에 반영해야 기능을 실제 서버에서 사용할 수 있다. 활성 컨테이너는 연결된 참가자를 끊을 수 있어 여기서는 재생성하지 않았다.

## 검증

MariaDB/Redis Testcontainers의 친구·계정 검색·알림·공개 설정 관련 통합 검사 12개가 통과했다. 친구 요청 동의 설정, 자기 요청 차단, 중복·교차 요청, 수락·거절·취소, 24시간 대기, 제3자 권한 거부, 재요청 시 UUID 회전과 대문자 UUID 경로, 50개 대기 상한 및 이동 60초 요청 rate limit의 429 `{code: RATE_LIMITED}` 응답을 확인했다. 검색 회귀는 NFC/공백 정규화와 `%`·`_` 리터럴 처리, 결과 상한 20, 관계 상태·개인 정보 제한, 자기/비활성/차단 계정 제외, 최근 60초 60회 검색 제한을 확인한다. 알림 회귀는 새 요청·수락 outbox 행, 중복 요청 억제, 수신 거부 후 무대기열을 확인하고, 테스트용 구독을 등록해 발송 직전 opt-out과 DND 재검사가 provider 전송을 막고 각각 `NOT_DELIVERABLE`·`SUPPRESSED_DND`로 끝나는 것을 검증한다. 외부 VAPID endpoint에는 요청하지 않는다. 공개 회귀는 기본 비공개, opt-in 때만 온라인 표시, 해제 즉시 숨김, 위치 필드 부재와 차단 후 전체 결과 제외를 확인한다. 다중 World 차단 검사는 양방향 대기 요청이 차단 시 삭제되고 해제 뒤 복구되지 않는 점을 확인했으며, 탈퇴 통합 검사는 친구 관계와 요청 설정의 삭제를 확인한다.

프론트 Vitest 전체 73/73, TypeScript 검사, 84개 Java 레코드와 TypeScript 계약 검사, 변경 파일 Prettier 검사, OpenAPI YAML 파싱, production build가 통과했다. 서비스 워커 회귀 검사 3개에서 열린 앱의 친구 요청 갱신, 백그라운드 수락 알림, 알림 클릭 후 친구 창 열기를 확인했다. Testcontainers 친구/차단/탈퇴 통합 검사 12개와 World Redis presence 검사 2개도 통과했다. 백엔드 `:apps:api:test`와 `:apps:world:test` 전체는 앞선 실행에서 통과했다. production build는 성공했으며 기존 Phaser 관련 번들 크기 경고가 남아 있다.

운영 기능 적용과 별도 검증을 구분한다. 2026-09-29 운영 API는 현재 불변 릴리스에서 실행 중이며, 서버에서 Web Push VAPID 키를 설정하고 API 컨테이너만 재생성해 알림 발송 구성을 활성화했다. 준비 상태와 환경 주입 여부는 확인했지만 실제 HUFS SSO 두 계정 간 요청·수락과 브라우저 푸시 권한·provider 전달은 확인하지 않아 이 검수는 미완료다([운영 증거](evidence/31-webpush-production-config-2026-09-29.json)).
