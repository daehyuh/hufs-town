# 공간 즐겨찾기

2026-09-22. 공간 홈에서 자주 찾는 공간을 빠르게 열 수 있도록 사용자별 즐겨찾기 저장과 필터를 연결했다.

## 동작

- 공간 카드 별표를 누르면 즐겨찾기를 추가하거나 해제한다. API 응답 전 카드 상태를 먼저 바꾸고 요청이 실패하면 원래 상태로 되돌린다.
- `즐겨찾기` 필터는 서버가 확인한 현재 계정의 저장 공간만 보여주고, 공통 검색·페이지네이션을 적용한다. 저장한 UNLISTED 공간은 목록에서 다시 찾을 수 있지만, PRIVATE 공간은 멤버십이 사라지면 이름을 노출하지 않는다.
- 즐겨찾기는 `app_user`와 `town_space`의 쌍으로 저장한다. 한 사용자의 변경은 다른 계정의 카드에 영향을 주지 않는다.
- 추가는 공간 행을 잠근 트랜잭션 안에서 계정 활성·공간 읽기·차단 정책을 확인한다. 이미 추가된 공간은 `INSERT IGNORE`로 멱등 처리한다. 해제는 접근이 바뀐 뒤에도 사용자가 저장 표시를 지울 수 있도록 소유자의 즐겨찾기 행만 삭제한다.
- 목록과 상세/생성 응답의 `favorite` 필드는 호출자 기준 값이다. API 쓰기는 기존 CSRF·분당 60회 쓰기 제한을 따른다.

## 저장 변경

Flyway V22가 `space_favorite(user_id, space_id, created_at)` 테이블을 생성한다. 복합 기본 키가 중복을 막고, 공간별 조회용 인덱스와 계정/공간 외래 키를 둔다.

## 최근 방문 공간

실제 월드 연결이 성공했을 때만 `SpaceLobby`가 로그인 사용자 ID별 브라우저 저장소에 공간 ID와 방문 시각을 기록한다. 홈의 `최근 방문` 탭은 저장된 각 공간 ID를 기존 상세 조회 API로 다시 확인해 표시하므로 공개 범위 변경이나 멤버십 회수 뒤에는 읽기 권한이 없는 공간의 이름을 노출하지 않는다. 사라진/접근 불가 공간은 저장 목록에서도 정리하고, 일시적인 API 오류는 목록을 비우고 경고 및 새로고침 경로를 제공한다. 검색은 최근 방문 결과에도 적용된다.

이 기록은 편의 기능이며 서버나 다른 기기와 동기화하지 않는다. 브라우저에는 계정별 공간 ID와 시각만 저장하고 이름·설명·프로필은 보관하지 않는다.

## 남은 범위

실제 다중 SSO 계정의 저장 분리와 권한 변화에 따른 UI는 수동 검증이 필요하다. 서버 목록은 offset 기반 페이지네이션이며, 대규모 공간 카탈로그가 생기면 검색 인덱스와 cursor 방식으로 전환을 검토한다.

2026-09-24: 두 브라우저 Playwright에서 월드 연결 전에는 방문을 기록하지 않고, 실제 연결 이후 계정별 기록을 보여주는 흐름과 읽기 권한이 사라진 공간을 목록에서 제거하는 동작을 확인했다. 최근 방문·검색은 Vitest 37/37, 관련 E2E 2/2, Prettier와 production build가 통과해 T08.1을 완료했다. 테스트 SSO/브라우저 컨텍스트이며 실제 HUFS IdP 계정 검증은 T06.2에 남는다.
