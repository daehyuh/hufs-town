# 01. 제품 요구사항과 완성 범위

## 1. 제품 정의

가칭 **HUFS Town**. GDG HUFS 구성원, 외부 행사 참여자, 스터디 운영자가 같은 브라우저 공간에서 대화·발표·협업하고 공간을 직접 꾸미는 2D 온라인 플랫폼이다. 인증은 후속 사용자 결정에 따라 **GDG HUFS SSO**를 사용한다. 참조 서버와 같은 코드 교환 규격을 따르며 Gmail 메일함 접근 권한은 필요하지 않다. 외부 행사 참여자의 별도 입장 정책은 공간·초대 태스크에서 확정한다.

확정 조건은 공간당 동시 접속 100명이며, AI가 처음부터 끝까지 전체 구현을 수행한다. 개발 일정은 두지 않고 계획·태스크·선행 조건·완료 기준으로 관리한다. 전체 서비스 동시 접속 수는 미정이므로 초기 부하 시험은 1개 공간 100명, 후속 확장 시험은 10개 공간 합계 1,000명으로 별도 수행한다. 두 번째 수치는 초기 보장 용량이 아니다.

프론트는 **React 기반 웹**으로 확정한다. 백엔드 기본안은 사용자의 Spring 선호를 반영한 **Spring Boot·MariaDB·Redis**이며, 실시간 이동은 Spring WebSocket, 음성·영상·화면공유는 별도 WebRTC SFU로 처리한다.

지원 우선순위는 데스크톱 Chrome·Edge의 현재/직전 주요 버전 → macOS Safari·Firefox → 모바일 참가 기능 순서다. R1에 모바일 입장·이동·채팅·음성·영상 수신을 포함하고, 모바일 화면 송출과 맵 편집은 브라우저 지원 여부에 따라 데스크톱 이용 안내를 제공한다. 모바일 네이티브 앱은 후속 범위다.

## 2. 릴리스 정의

- **R0 내부 알파:** 로그인, 템플릿 공간, 초대, 이동, 근거리 음성·화상, 독립 회의실, 화면공유, 기본 아바타·채팅이 실사용 가능하다.
- **R1 정식 공개:** 요청 기능 전체 + 맵 편집/게시 + 행사/운영 + 차단/신고 + 백업/장애 복구 + 100명 부하 기준을 통과한다.
- **R2 고도화:** 공동 편집, 화이트보드, 녹화·자막, 미니게임·확장 앱, 분석, 외부 연동을 단계적으로 추가한다.

R0를 최종 완성품으로 간주하지 않는다. 경쟁 제품의 모든 요금제 기능과 완전히 같다는 의미의 복제가 아니라, 이 제품의 사용 목적에 필요한 범위를 명세로 고정한다.

## 4. 핵심 사용자 흐름

### 첫 참가

초대 링크 → 공개 정보 확인 → GDG HUFS SSO 로그인 → 초대 상태 재검증 → 닉네임·아바타 → 마이크/카메라 테스트 → 필요 시 대기실 → 스폰 → 30초 조작 안내 → 주변 대화.

기기 권한을 거부해도 텍스트·듣기 전용으로 입장할 수 있다. 입장 시 카메라/마이크는 기본 꺼짐이며, 테스트 화면에서 사용자가 선택한 상태를 명확히 확인한 후 적용한다. 화면공유는 별도 클릭이 필요하다.

### 공간 만들기

내 공간 → 새 공간 → 캠퍼스/스터디/밋업 템플릿 → 공개 범위·입장 정책 → 생성 → 맵 꾸미기 → 미리보기 → 게시 → 초대 링크 복사. 실제 이메일 초대 발송은 별도 명시적 동작으로 구현하고 발송 서비스·반송 처리를 갖춘다.

### 대화와 발표

가까운 사람과 자동 연결 → 상단에 연결 대상과 통화 범위 표시 → 독립 회의실 입장 시 대상 전환 → 필요 시 잠금 → 화면공유 → 퇴실 시 즉시 공유 중단. 발표자는 운영자가 지정하며, 일반 참가자는 손들기로 발언권을 요청한다.

### 맵 편집

편집 권한 확인 → 초안 편집 → 자동 저장 → 검증 결과 확인 → 게시 → 현재 접속자는 안전한 게시 버전으로 전환 → 장애 시 이전 버전 복구.

목록 노출과 입장 자격을 별도 속성으로 저장한다.

| 프리셋 | 목록 | 기본 입장 자격 |
|---|---|---|

## 7. 반드시 명확해야 하는 동작

- **전체 공유:** 사용자가 전체 모임에 들어가 자기 마이크·카메라를 켤 수 있고 전체 참가자가 접근 가능한 상태가 된다. 실제 수신은 활성 발화자·화면에 보이는 영상·개별 고정 선택을 기준으로 제한한다. 100개의 영상을 동시에 디코딩하는 보장은 하지 않는다.
- **근거리:** 거리 조건은 사용자 쌍마다 판단한다. A-B, B-C가 가까워도 A-C가 멀면 연결하지 않는다.
- **회의실:** 같은 회의실에서는 거리와 무관하게 대화하며, 다른 회의실과 복도에는 전달하지 않는다.
- **비공개 회의실에서 발표 듣기:** 기본 비활성. 사용자가 회의를 나와 행사에 참여해야 한다. 텍스트 공지는 수신할 수 있다.
- **자리비움:** 설정 시간 후 표시하며 기본적으로 송출을 일시 중지한다. 복귀 때 상태를 안내한다.
- **찌르기:** 같은 공간의 허용 대상에 한해 알림·짧은 효과를 보낸다. 차단·DND·개인 설정·재사용 대기시간을 우선한다.
- **달리기:** 이동 속도만 변경한다. 충돌·회의실 잠금·맵 경계를 통과하지 못한다.
- **재접속:** 동일 사용자에 중복 아바타를 만들지 않으며 복구 후 위치와 통화 범위를 다시 검증한다.

## 8. 제안 제한값과 합격 기준

다음은 설계 초기값이며 측정 결과에 따라 조정한다.

| 항목 | R1 초기값 |
|---|---|
| 공간 정원 | 전체 맵 합계 100명, 관전자 포함 |
| 근거리 대화 대상 | 1인당 최대 12명, 화면 영상 8개 기본 |
| 독립 회의실 | 일반 12명, 큰 회의실 25명; 초과 시 발표형 전환 |
| 전체 모임 | 최대 100명 참가·송출 가능, 수신 영상 8~12개·활성 음성 선택 |
| 화면공유 | 1인 1개, 한 대화 영역 2개까지 송출·1개 집중 수신 기본 |
| 첫 지도 | 64×48 논리 타일 권장, 256×256 타일 상한 후보 |
| 채팅 | 1메시지 2,000자, 속도 제한, 근거리 내용은 기본 비영속 |
| 사용자 이미지 | PNG/WebP 우선, 5MB·2048×2048 상한 후보 |
| 찌르기 | 같은 대상 30초 대기, 사용자별 분당 5회 초기값 |

R1 완료 조건은 기능 체크뿐 아니라 100명 통합 부하, 권한 분리, 1시간 회의, 다중 기기, 맵 게시 복구, 운영자 시나리오가 통과하는 것이다. 상세한 측정 조건은 구현 계획을 따른다.

## 9. 범위 밖 또는 후순위

3D/VR, 자체 WebRTC 코덱, NFT/토큰, 범용 사용자 코드 실행, 기본 자동 녹화, 전 세계 다중 리전 동시 배포, 100명 고해상도 영상 전체 동시 디코딩은 초기 범위에 넣지 않는다. 에셋 거래·결제는 운영 필요가 확인된 뒤 추가한다.
