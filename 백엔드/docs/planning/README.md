## 핵심 결정

**인증 변경:** Google OAuth 계획을 GDG HUFS SSO로 교체했다. 참조 서버 규격과 관리자 준비 항목은 [SSO 연결 안내](../development/hufs-sso.md)를 따른다. 로그인 코드·세션·프로필·월드 인증과 계정 탈퇴 경로를 구현했다. 자동화 검사는 외부 IdP를 모의하며, 실제 IdP 재로그인·신규 계정 생성 검증은 남아 있다.

1. **2D 도트 월드 + 읽기 편한 웹 UI.** 게임 화면은 Phaser, 메뉴·통화·에디터 패널은 React로 만든다.
2. **위치와 미디어를 분리한다.** Spring WebSocket 월드 서버가 이동·충돌·현재 구역을 판정하고, WebRTC SFU가 음성·영상·화면을 전달한다.
3. **서버가 상태와 권한의 기준이다.** 클라이언트 좌표, 비공개 구역 주장, 음소거 UI를 권한의 근거로 사용하지 않는다.
4. **100명 접속과 100명 영상 수신은 별도 문제다.** 근거리 대화, 회의실, 전체 모임, 발표 모드마다 구독량과 화면 구성을 다르게 정한다.
5. **맵은 초안과 게시본을 구분한다.** 가구를 자유롭게 편집하되, 실제 사용자 위치·충돌·통화 경계에 영향을 주는 변경은 검증 후 적용한다.
6. **완성 범위는 줄이지 않고 릴리스를 나눈다.** 사용자가 요청한 기능은 R1 정식 버전에 모두 포함하고, 고급 협업·콘텐츠·수익화는 R2로 구분한다.
7. **AI가 전체 구현을 태스크 단위로 진행한다.** 설계 보완부터 코드·테스트·배포 설정·운영 문서까지 수행하고, 선행 조건·산출물·완료 증거로 관리한다. 개발 일정과 인력 투입 추정은 사용하지 않는다.
8. **Gather·ZEP을 구체적인 화면 레퍼런스로 사용한다.** 플레이·회의는 Gather Classic, 공간·맵 관리는 ZEP을 기준으로 하고 GDG HUFS 에셋을 적용한다. 화면별 대응과 확인 자료는 07 문서를 따른다.

## 권장 기술안

**프론트:** React + Vite + TypeScript + Phaser.

**백엔드:** 사용자 선호를 반영한 Java + Spring Boot + Spring Security + Spring WebSocket / MariaDB + Spring Data JPA + Flyway / Redis / S3 호환 스토리지 + CDN.

이동 중 상태는 담당 월드 서버 메모리, 영속 데이터는 MariaDB, 접속·입장 예약·캐시는 Redis가 담당한다. Spring에서 월드 동기화·변경분 전송·재접속을 구현하는 태스크를 명시하고 공간당 100명을 부하 검증한다.

미디어는 **LiveKit Cloud를 첫 검증 후보**로 둔다. 단, 서버에서 계산한 수신 권한을 확실히 강제할 수 있는지 G0에서 확인한 뒤 채택한다. 단순 `autoSubscribe: false`는 접근 통제가 아니다. 이 조건을 충족하지 못하면 **mediasoup + coturn**을 검증해 확정한다. 엔진 선택은 필수 기능과 권한 검증 결과로 결정하며, 하나의 채택 엔진으로 제품을 구현한다.

## 용어

| 용어 | 의미 |
|---|---|
| Space / 공간 | 생성·초대·공개 설정·멤버십·100명 정원을 갖는 상위 단위 |
| Map / 맵 | 공간 안의 로비·카페·강당 등 실제 이동 지도 |
| Zone / 구역 | 한 맵의 근거리 영역, 독립 회의실, 무대, 무음 구역 |
| Session / 접속 세션 | 현재 로그인 사용자의 한 번의 접속. 중복 탭과 재접속을 구분 |
| Media domain / 통화 영역 | 서로 미디어를 전달할 수 있는 논리적 경계. 맵이나 공간과 1:1일 필요 없음 |
| World instance / 월드 인스턴스 | Spring 월드 프로세스가 소유하는 한 맵의 실시간 상태와 직렬 처리 단위. 사용자에게 보이는 회의실과 다른 개념 |

## 현재 작업공간 사실

- 백엔드와 프론트엔드 앱, 계약 파일, MariaDB·Redis Docker 개발환경이 있으며 SSO 로그인으로 캠퍼스 월드 접속을 확인했다.
- 디자인 에셋 분석과 런타임 선별 복사는 완료했다. 캐릭터 프레임·다양한 템플릿 및 실제 배포 권한 확인은 실행 기록의 남은 범위를 따른다.
- 외부 SSO는 실제 개발 계정으로 로그인·월드 입장을 확인했으며 자동 통합 테스트에서는 전송을 모의한다. 계정 탈퇴의 자동 통합 시나리오는 별도 테스트용 MariaDB·Redis로 검증한다.

## 첫 구현 단위

**GDG 테스트 맵에 사용자 A·B·C가 접속 → A와 B만 가까울 때 대화 → B가 독립 회의실로 이동하면 기존 대화 종료 → C와 같은 회의실에서만 대화 → B의 화면이 해당 회의실에만 표시**되는 수직 기능을 먼저 완성한다. 함께 아바타 이동·스프라이트·TURN 접속·권한 취소 동작을 확인한다.

이 결과로 미디어 엔진과 프로토콜을 확정한 다음 로그인·공간 관리·본격 에디터·행사 기능을 쌓는다. 데모용 인증은 G0의 로컬 테스트에만 허용하며 공개 환경에 배포하지 않는다.
