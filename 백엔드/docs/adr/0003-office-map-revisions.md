# ADR 0003: 카탈로그 기반 오피스와 불변 게시 맵

상태: 채택. 범위: 현재 단일 API/월드 로컬 런타임.

맵은 서버와 브라우저가 공유하는 JSON schema v2로 정의한다. 바닥·벽·오브젝트·구역·라벨·시작점을 분리하고 모든 위치는 32px 타일 단위다. 오브젝트 위치는 아래쪽 중앙이며 카탈로그에 크기와 충돌 footprint를 고정한다. 직접 SVG/URL을 맵에 삽입할 수 없다. 현재 허용된 카탈로그 ID만 배치할 수 있다.

제공된 게임 에셋의 현대식 가구 부족을 코드 기반 픽셀 SVG로 보완한다. 카탈로그와 기본 맵 생성기는 재실행 가능하다. 캐릭터는 제공된 프레임 시트를 사용한다. 서버 충돌과 편집 미리보기는 같은 카탈로그 데이터를 따른다.

초안과 불변 게시본은 MariaDB JSON으로 저장한다. 최대 512KB의 작은 맵에는 별도 객체 저장소 도입보다 현재 DB 트랜잭션과 관리 경로를 공유하는 것이 단순하다. 향후 사용자 에셋 바이너리는 별도 격리 업로드 경로를 추가한다.

초안은 SQL 행 잠금, 세션/탭 바인딩 lease, 만료와 fence, optimistic draftVersion, idempotency operation ID로 보호한다. 마지막 쓰기 우선 덮어쓰기를 사용하지 않는다. 동일 계정의 다른 탭도 별도 작성자다. UI의 읽기 모드와 명시적 인계는 서버 판정을 따른다.

게시 포인터와 outbox를 동일 트랜잭션에 기록한다. 전달 실패는 outbox가 재시도하고 Redis 갱신은 sequence가 증가할 때만 수락한다. 접속한 월드는 Redis 캐시를 주기적으로 조회해 놓친 알림을 회복하고, 자체 actor에서 새 맵을 적용한다. 서버가 mapChanged와 새로운 입력 epoch를 보내고 클라이언트는 이전 revision snapshot을 무시한다. 충돌 안에 남은 참가자를 안전한 spawn으로 옮긴다.

한계: 현재 outbox 전달 완료는 Redis 반영까지를 의미한다. 다중 노드의 대상별 적용 ACK와 RTC policy epoch 연계는 T20.2/T13에서 확장한다. 현재 단계에서 분산 월드 게시 완료나 통화 분리를 보장한다고 주장하지 않는다.
